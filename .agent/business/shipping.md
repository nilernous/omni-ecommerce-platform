## 1. Domain Overview & Purpose
The **Shipping Service** calculates shipping fees and estimated delivery windows, integrates with logistics carriers (FedEx, UPS, DHL, Local Carriers), generates shipping labels, tracks carrier shipments, and notifies customers of delivery progress.

---

## 2. Core Business Rules & Validations

### Shipping Rate Calculation Rules
- **SHIP-BR-01: Rate Input Parameters**: Shipping fees are computed based on `originPostalCode`, `destinationPostalCode`, `totalDimensionalWeight` (kg), and `serviceTier` (Standard, Express, Overnight).
- **SHIP-BR-02: Volumetric Weight Formula**: `Volumetric Weight (kg) = (Length x Width x Height in cm) / 5000`. Billable weight is `MAX(Actual Weight, Volumetric Weight)`.
- **SHIP-BR-03: Free Shipping Threshold**: Orders with `Subtotal >= $100.00` qualify for standard free shipping (unless overridden by promotional campaigns).

### Shipment Generation & Fulfillment Rules
- **SHIP-BR-04: Fulfillment Prerequisite**: Merchants (`SELLER`) can generate shipping labels only after order status is `PAID`.
- **SHIP-BR-05: Mandatory Carrier Information**: Creating a shipment requires assigning a valid carrier tracking number (`trackingNumber`) and carrier code (`carrierCode`).
- **SHIP-BR-06: Label File Format**: Generates printable PDF / ZPL shipping label files stored via Media Service.

### Delivery Tracking Rules
- **SHIP-BR-07: Real-Time Tracking Ingestion**: Polls carrier APIs or receives webhook tracking updates.
- **SHIP-BR-08: Auto-Completion Return Window Trigger**: When carrier marks status `DELIVERED`, the system updates order status and initiates the 7-day customer return countdown window.

## 3. Shipment Lifecycle & Carrier Statuses

```text
[LABEL_CREATED] ──► [PICKED_UP] ──► [IN_TRANSIT] ──► [OUT_FOR_DELIVERY] ──► [DELIVERED]
       │                                                                  │
       └──(Carrier Exception)──► [EXCEPTION]                              └──► [FAILED_DELIVERY]
```

- **SHIP-BR-09: Status `LABEL_CREATED`**: Shipping label generated by merchant; awaiting carrier pickup.
- **SHIP-BR-10: Status `PICKED_UP`**: Package scanned into carrier origin hub.
- **SHIP-BR-11: Status `IN_TRANSIT`**: Package moving between carrier transit hubs.
- **SHIP-BR-12: Status `OUT_FOR_DELIVERY`**: Package loaded on local delivery truck for final leg delivery.
- **SHIP-BR-13: Status `DELIVERED`**: Package handed to recipient or dropped at delivery address.
- **SHIP-BR-14: Status `FAILED_DELIVERY`**: Delivery attempt failed (recipient unavailable, wrong address).

## 4. REST API Endpoints & Access Control

| Method | Endpoint | Access Level | Description |
|---|---|---|---|
| `POST` | `/api/v1/shipping/calculate-rate` | Public / Customer | Calculate shipping rate options for checkout |
| `POST` | `/api/v1/shipping/shipments` | Seller / Admin | Generate carrier shipment & shipping label |
| `GET` | `/api/v1/shipping/shipments/{id}/track` | Customer / Seller / Admin | Get real-time carrier tracking timeline |
| `POST` | `/api/v1/shipping/webhook/{carrier}` | Public (Carrier Webhook) | Carrier shipment status update webhook |

## 5. Domain Events Emitted & Consumed

### Emitted Events
- **SHIP-BR-15: Event `shipping.label_created`**: Emitted when merchant generates shipping label.
- **SHIP-BR-16: Event `shipping.dispatched`**: Emitted when package is picked up by carrier. Triggers order status `SHIPPED`.
- **SHIP-BR-17: Event `shipping.delivered`**: Emitted on confirmed delivery. Triggers order status `DELIVERED`.

### Consumed Events
- **SHIP-BR-18: Consumer `order.paid`**: Prepares order for merchant shipping fulfillment.
